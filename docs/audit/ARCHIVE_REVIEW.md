# Проверка архивируемых отчётов

Дата проверки: 2026-10-10.

Перед переносом восьми корневых отчётов выполнен поиск абсолютных локальных путей, email, телефонов, IP, ФИО-подобных данных, секретов и формулировок о незакрытых рисках.

| Отчёт | Результат проверки |
|---|---|
| `docs/archive/BULK_SELECTION_AUDIT.md` | Абсолютных путей и персональных данных нет. Строка 86 описывает semantic tokens, а не security token. |
| `docs/archive/CONTINGENT_RECONCILIATION_AUDIT.md` | Персональные данные отсутствуют; строки 126–150 и 202 описывают реализованные token/CSRF/password-защиты. Строки 227–229 фиксируют непройденную физическую UI-матрицу, это остаточный QA-gap. |
| `docs/archive/DESKTOP_UPDATES_AUDIT.md` | Значений секретов нет. Строки 45 и 67 описывают сохранение локальных данных и CI-переменные code signing без их содержимого. |
| `docs/archive/DEVELOPER_INFO_SHORTCUT_AUDIT.md` | Персональных данных и уязвимостей нет. Строка 49 фиксирует отсутствие отдельного hover-снимка. |
| `docs/archive/LIVE_SEARCH_AUDIT.md` | Персональных данных нет. Строка 74 фиксирует отсутствие ручного browser-прогона; автоматические проверки присутствуют. |
| `docs/archive/TOPBAR_UPLOAD_LAYOUT_AUDIT.md` | Персональных данных нет. Строка 69 описывает тестовый loopback-сервер и одноразовый пароль; значения в отчёте нет. |
| `docs/archive/UI_MODERNIZATION_REPORT.md` | Значений секретов нет. Упоминания паролей/CSRF относятся к реализованным защитам; незакрытая уязвимость не описана. |
| `docs/archive/UI_REGRESSION_AUDIT.md` | Персональных данных и незакрытых security-проблем нет; совпадения со словом token относятся к design tokens. |
| `docs/archive/WINDOWS_RELEASE_PIPELINE_AUDIT.md` | Перенесён из `docs/` позднее остальных. Абсолютных путей, персональных данных и значений секретов нет; описывает уже внедрённую проверку draft-релиза. Актуальное поведение — в `.github/workflows/windows-release.yml`. |

ФИО-регулярное выражение давало ложные совпадения на обычных русских предложениях; структурированных строк с ФИО, телефонами или email в отчётах не найдено.

## Остаточные пункты

- При будущих изменениях reconciliation/upload UI выполнить физический drag-and-drop и матрицу тем.
- Для live search и developer shortcut сохранить ручной browser smoke в release checklist.
- Не использовать архивные отчёты как актуальную security-документацию; источником истины служат `SECURITY.md` и `docs/audit/SECURITY_FINDINGS.md`.
