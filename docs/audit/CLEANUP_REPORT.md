| Доверие Git-релизу сервера | Частично снижено | Нужна обязательная подпись тега или проверка provenance attestation. |
| Desktop update | Частично снижено | Signed-сборки проверяют Authenticode pin; unsigned SHA-256 не подтверждает издателя. |
| Открытый HTTP в сети | Задокументировано и диагностируется | Для production обязательны HTTPS reverse proxy/VPN и secure cookies. |
| Резервные копии | Улучшено | Есть integrity, приватные права и retention; шифрование остаётся внешней обязанностью. |
| Зависимости | Улучшено | CI отдельно проверяет `requirements-prod.lock` и `requirements-desktop.lock`. |

Полный первичный протокол находится в [SECURITY_FINDINGS.md](SECURITY_FINDINGS.md).

## 4. Ручная очистка истории при будущей подтверждённой утечке

Ниже — runbook, а не выполненные команды. Сначала отозвать credential, затем
работать только в отдельной mirror-копии и согласовать окно обслуживания.

```bash
git clone --mirror <repository-url> manticore-sanitized.git
cd manticore-sanitized.git
gitleaks detect --source . --log-opts="--all" --redact

# Один подтверждённый чувствительный путь:
git filter-repo --path '<sensitive-path>' --invert-paths --force

# Либо подтверждённые строковые секреты по локальному файлу правил:
git filter-repo --replace-text '<local-replacements-file>' --force

# Только после проверки mirror-копии и явного согласования владельца:
git push --force --mirror <replacement-remote>
```

После публикации все старые клоны и открытые PR должны быть пересозданы. Очистка
истории не заменяет ротацию: старый ключ сначала отзывается у провайдера, новый
создаётся с минимальными правами, сохраняется вне Git, затем проверяются audit logs.
