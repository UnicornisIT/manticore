# Структура проекта

| Путь | Назначение |
| --- | --- |
| `app.py` | Фабрика/сборка Flask-приложения и совместимая прикладная обвязка. |
| `config.py` | Типизированная загрузка runtime-настроек. |
| `routes/` | Blueprints по доменам auth, abiturients, students, files, admin, migration и management. |
| `services/` | Импорт файлов и чистая логика сверки без Flask-контекста. |
| `db/` | Упорядоченный реестр версионных миграций SQLite. |
| `db_safety.py` | Целостность, schema version, backup/restore и приватные права файлов. |
| `contingent.py` | Совместимый публичный импорт для `services/reconciliation.py`. |
| `contingent_web.py` | Веб-обвязка операций сверки контингента. |
| `email_validation.py` | Синтаксис, DNS-проверка и справочник почтовых доменов. |
| `data/email_providers.json` | Версионируемый статический справочник провайдеров; не runtime-данные и не PII. |
| `desktop_releases.py` | Разрешённые сервером релизы Windows-клиента. |
| `desktop/` | pywebview-клиент, updater и инструменты выпуска. |
| `app_metadata.py` | Единый источник публичного имени и контактов приложения. |
| `sync_app_metadata.py` | Синхронизация сгенерированного блока контактов README. |
| `deploy/` | Шаблоны systemd, Nginx и ограниченного sudoers. |
| `scripts/` | Канонические скрипты запуска и обновления; файлы в корне — обёртки. |
| `static/`, `templates/` | Веб-интерфейс и шаблоны выгрузок. |
| `tests/` | Python unit/integration и frontend regression tests. |
| `docs/` | Пользовательские, эксплуатационные и архивные документы. |
| `docs/releases/` | Заметки к опубликованным выпускам. |
| `.github/` | CI (`ci.yml`), проверки безопасности (`security.yml`), выпуск Windows-клиента, шаблоны issue и PR. |
| `VERSION` | Единая версия приложения и пакета. |
| `RELEASE_CHECKLIST.md` | Обязательные проверки перед выпуском. |
| `pyproject.toml` | Метаданные пакета, extras, Ruff и mypy. |

Runtime-файлы создаются в `uploads/` либо по путям из `.env`: база SQLite,
загрузки, выгрузки, журналы, status-файлы и резервные копии. Они не являются
частью исходного кода и должны оставаться игнорируемыми Git. Для тестов
используются только синтетические данные и временные каталоги.

Исторические отчёты и прежние инструкции сохранены в `docs/archive/`. Они нужны
для аудита решений, но не должны использоваться как актуальное руководство.
